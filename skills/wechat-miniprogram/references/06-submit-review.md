# 06 · 上传、审核与发布（Submit & Review）

> 阶段目标：完成上传 → 审核 → 发布的完整流程，并在被拒时标准化修复。

## 一、上线前检查清单（详见 `assets/release-checklist.md`）

审核被拒 80% 源于这 6 类问题，上传前 3 分钟过一遍：

1. **功能正常**：每个按钮/输入/跳转点一遍，无报错（看 `bindtap`/`catchtap`、控制台红错）。
2. **页面加载**：每页打开无空白；弱网下（Slow 3G）测 3 次；首屏 3 秒内须展示。
3. **广告合理**：不遮挡核心按钮，不在完成任务前弹，首屏不弹窗。
4. **版本描述填写**：让审核员看懂你改了啥（见模板）。
5. **类目选对**：工具类选「工具 → 细分类目」，别选错成金融/社交（需资质）。
6. **真机预览过**：手机走完所有功能；必测广告组件、保存图片、分享卡片、微信登录。

## 二、上传代码

- 微信开发者工具 → 「上传」→ 填版本号与备注。
- **版本号规范** `主.次.修订`：
  - 修订补丁（修 Bug/小优化）→ 第 3 位 +1（1.0.0→1.0.1）
  - 特性更新（新增功能向下兼容）→ 第 2 位 +1、第 3 位归零（1.0.0→1.1.0）
  - 版本升级（重大/可能不兼容）→ 第 1 位 +1（1.0.0→2.0.0）
- 版本号只是给人/团队看的标签；微信实际比对"提审次数"。
- 首次提交需在后台设为「体验版」。

## 三、提交审核

- 填版本描述（必填）、建议传图片/视频预览；有测试账号/隐私采集按需填。
- 审核时间：常规 1–7 工作日（平均 1–2 天），加急每年 3 次（2–4 小时）。
- 若采集用户信息（头像/昵称/手机号/位置/相册），必须补《用户隐私保护指引》。

## 四、通过后发布

- 默认全量发布；发布后约 1–2 天才能在微信搜索到。

## 五、被拒怎么办（标准化排查）

按驳回原因逐条改，再重提，不要赌"换个审核员"。

1. **功能太简单/不完整**：至少补齐一个完整可用的核心闭环（查询/记录/生成结果/收藏之一）。
2. **名称/简介/版本说明太虚**：别写"工具助手""智能平台"，写清具体服务。
3. **类目不符**：按"实际提供什么服务"选，或删掉越界功能再提。
4. **功能同质化**：说清服务谁、解决啥问题（如"健身记录打卡"而非"每日打卡"）。
5. **隐私/权限**：用了什么权限就在指引里写清为什么、收集什么、用于啥；后台声明+前端弹窗+实际调用三件事对上。
6. **支付/会员/课程**：主体/类目/支付不匹配时，先去掉付费链路再提，资质齐了再上。

## 六、给 AI 的交付动作

- 产出「版本描述」文案（首次发布/修 Bug/新增功能/调广告 四类模板）。
- 帮用户按实际功能判断正确类目（工具→计算器 / 工具→信息查询 / 工具→记账…）。
- 被拒时，对照驳回原因给逐项修改清单，并提醒在版本说明写清改了啥。
- 隐私类问题务必提醒"后台声明 + 前端弹窗 + 调用逻辑"三者一致。
