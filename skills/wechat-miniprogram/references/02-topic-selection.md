# 02 · 选题与需求判断（Topic Selection）

> 阶段目标：用一个可复制的判断框架，帮用户选出"个人开发者能做、竞争小、有真实需求"的小程序方向。

## 一、选需求的三个核心标准（每条方向都要过）

1. **功能要单一**：一个小程序只解决一个问题。功能越多 → 开发越复杂、出 bug 概率越大、审核越难过、用户越不知道它是干啥的。
2. **使用场景要清晰**：能回答"用户在什么情况下会打开它？" 越具体越好（如"打牌记分""体检完算 BMI"）。反面："生活助手"太模糊。
3. **无明显头部垄断**：微信搜一搜搜关键词，若前面全是腾讯/支付宝等大厂产品 → 换方向；若排的是普通小工具 → 有机会。

## 二、找需求的两种方法

### 方法一：从自己生活出发（最靠谱）

- **看自己常用**：微信首页下拉"最近使用"的小程序，你对它的痛点理解最深。
- **回忆近一周**：有没有"想算个啥但没有工具""聚会要记分/摇骰子/AA"的念头。
- **问身边人**：家人/朋友/同事常用什么小程序（万年历、记工时、打牌记分、BMI…）。

### 方法二：分类浏览建立全局认知

- 微信 → 发现 → 小程序 → 拉到底部分类目录 → 重点关注「效率与工具」。
- 看到每个小工具问自己：它解决什么问题？我用 AI 能做出来吗？身边有人需要吗？

## 三、五类已被验证的方向（个人可做）

| 方向 | 代表 | 为什么适合 |
| --- | --- | --- |
| 线下社交工具 | 打牌记分、摇骰子 | 天然裂变（一桌人都会用），无需推广 |
| 各类计算器 | BMI、保质期、房贷、单位换算 | 逻辑清晰、纯前端、1–3 天可做 |
| 行业垂直工具 | 记工计件、钢材计算 | 受众小但粘性极高 |
| 节日/场景工具 | 祝福语、亲戚关系计算器 | 特定时间流量爆发，需提前布局 |
| 心理测试类 | 性格/心理测试 | 爱玩爱分享，天然裂变 |

## 四、给 AI 的交付动作

- 用"三标准"帮用户快速过滤想法的清单。
- 产出「选题卡」：方向名 / 解决的具体问题 / 使用场景 / 竞品观察 / 推荐类目（工具→xxx）。
- 提醒用户：**先想清楚 5–10 个方向再动手**，避免"做一个想一个"拖慢节奏。
- 不要替用户承诺"这个方向能火"，只做可行性判断。
