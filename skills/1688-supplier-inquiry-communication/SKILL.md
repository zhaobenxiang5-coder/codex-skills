# 1688厂家询问沟通

找货策略版本：`stock-first-custom-fallback-v1`。  
定制沟通策略版本：`human-staged-v3`。
供应商网络策略版本：`core-pool-first-v1`。

这是跨产品通用流程。每次运行都视为新产品；产品结构、尺寸、材料、数量、价格和图片只能写进当次 X 项目 Brief 或运行批次，禁止写进本 Skill，也不得复用上一产品参数。

## 1. 统一入口：现货优先，定制兜底

每个产品只创建一个找货项目，不让用户在“现货/定制”中二选一：

```text
一次开始
→ 只读搜索可原样测试的现成商品
→ 同时准备可按方案打样的供应商
→ 有合适现货：交给用户判断是否拿样
→ 无合适现货或用户拒绝：直接继续已准备的定制供应商
```

现货只有在**不改结构、版型、核心功能或尺寸体系的前提下，能直接拿样测试**时才成立。需要任何修改的相似款只能当定制参考。商品页证据不能升级为厂家定制能力证据。

现货线全程只读：不自动问卖家、不下单、不付款、不上架。本轮为0是正常的 `no-match`，不算项目失败，也不启动持续监控。详细规则见 [sourcing-policy-v1.md](references/sourcing-policy-v1.md)。

进入定制兜底后，必须先匹配X中的优选/核心工厂池，再开放新厂外发：

```text
当前Brief与验收标准
→ 按品类赛道+工艺能力匹配1～3家优选/核心老厂
→ 用户逐厂预览并审批
→ 老厂用 seller chat --no-card 联系，不强绑无关Offer
→ 老厂拒绝、48小时无有效回复、全部不匹配，或用户填写原因手动解锁
→ 才允许向后台只读准备的新厂发送首询
```

新厂搜索和真实性初筛可以在后台只读运行，但老厂阶段未结束时新厂真实写任务必须为0。平台“源头工厂”标签、公司名或厂家单一自述不能证明真实制造；透明外协只有在范围明确且该厂对开发、质检、报价和交付负责时才可进入长期池。具体产品和厂家数据只存在X，不写入Skill。

新厂候选按三层处理，不能把最终样品目标当成外发门槛：

```text
原始召回池
→ 粗筛池（按项目 contactTarget 截取并去重）
→ 细筛沟通波（粗筛池约一半）
→ 首轮能力询问
```

`qualifiedTarget` 只表示最后要留下几家进入样品评估，不表示只允许同样数量的厂家先沟通。身份已补全、没有已知贸易商/身份冲突的 `unknown` 候选，可以进入首轮能力询问，用沟通补足生产和开发证据；明确 `likely-trader` 或身份冲突的候选必须挡住。细筛保留候选不能自动标记为合格，只有厂家书面声称、样品测试和后续履约证据才能继续升级。

### human-staged-v3 批次授权

- 首轮沟通波默认是粗筛池约一半，与最终 `qualifiedTarget` 分开计算。
- 用户一次批准整批候选、逐厂首询或续聊文字、完整阶段计划、已确认草图的 `assetId + SHA256`、24/48小时窗口和7天上限。
- 已有exact历史首询和真人回复的厂家必须复用原话与`messageId`，从缺失阶段继续；不得重新自我介绍。
- 当前有效活动会话少于首轮波目标时立即按缺口并行补位，不等待剩余1—2家全部超时；历史有效会话优先恢复，新厂家才消耗累计联系上限。
- 批次内普通追问、24小时提醒以及厂家愿意看图后发送批次已批准的同一张草图，不再弹出新审批。
- 新文件、Brief变化、批次外新增厂家，以及站外联系、地址、付款、下单、开模和采购承诺必须重新审批。
- 达到最终合格目标后停止全部新增写入，但继续只读同步已进入沟通厂家的迟到回复。
- 监控固定为：发送后30秒、首小时每5分钟、之后每30分钟；24小时无有效回复提醒一次；48小时停止；每次真人回复续48小时；首询后最多7天。
- 商品卡、卡片消息、营销和系统通知不是真人回复，不延长窗口，也不调用模型。

## 2. 进入定制兜底后的外发硬闸

用户说“跑一下”“找厂家”“批量问工厂”时，先完成以下事项，未完成只能只读准备：

1. 确认 `contactIntent.coreConcept`：一句话说明希望厂家配合做什么，不夹带问题、价格、MOQ、周期或地址。
2. 确认设计模式：
   - `locked-drawing`：结构已由用户和图纸锁定。
   - `collaborative-design`：允许厂家参与结构方案。
3. 整理版本化 Brief：`confirmed / unknown / supplier_to_propose / forbidden_to_assume`。
4. 每份图片先固定且只能选择一个用途：`search-reference`（仅1688识图找相似）、`supplier-drawing`（仅逐厂审批后给厂家看）、`analysis-only`（仅X内部分析）。禁止同一图片同时进入识图和厂家外发；后两类绝不进入1688识图。
5. 展示首轮批次的全部厂家、逐厂首询或续聊文字、获批草图、监听与停止条件，并取得一次批次批准。

任何影响外发内容的 Brief、设计事实或附件权限变化，都使旧预览和审批失效。

## 3. 设计事实与部件

图片识别只能产生 `image_inference`。只有用户明确确认后，才能写入：

```yaml
designIntent:
  mode: locked-drawing | collaborative-design
  approvedAssetIds: []
  lockedFacts:
    - fieldId: ...
      componentKey: ...
      description: ...
      sourceEvidenceIds: []
  adjustmentPolicy: follow-drawing-report-required-changes | supplier-may-propose
components:
  - componentKey: ...
    label: ...
    materialMode: fixed | supplier-to-propose
    materialCritical: true | false
```

`locked-drawing` 下，已确认的连接方式、扣具位置、开合/穿脱方式等不得重复询问。只有厂家主动质疑具体位置时，才能围绕该位置补问。 `collaborative-design` 才允许询问结构建议。

## 4. 厂家话术规则

- 每条厂家消息最多 **2个自然问题**；一个自然问题可映射多个内部字段。
- 恰好2个问题时才编号；1个问题不强制编号。
- 系统内部保存细字段、原话、连续证据和 `messageId`，但不能把字段问卷原样发给厂家。
- 模型只分析厂家回复，不自由创造要求或承诺。
- 每阶段最多2条自动消息；提醒占1条，附件不增加或重置轮数。
- 厂家提前回答后续信息时立即保存；进入对应阶段不得重复问。
- 每次真人回复续48小时，总窗口从首询验证时起最多7天。
- `manual_review`、模型失败、敏感操作、登录失效、风控或发送状态不明时，真实写入为0。

详细话术、批次自动沟通与阶段转移见 [dialogue-policy-v3.md](references/dialogue-policy-v3.md)。

## 5. 分阶段流程

```text
内部确认Brief
→ cooperation
→ awaiting-attachment-approval（需要时暂停）
→ core-feasibility
→ material-options
→ commercial-terms
→ final-review
→ stopped
```

### cooperation

首询只确认合作意愿：

> 老板你好，看到你们在做「{真实Offer标题}」。我们不是直接采购页面现货，而是在找愿意配合开发的工厂。我们准备开发{产品名}，核心方向是{已批准核心概念}。想先确认一下：你们是否愿意配合看图、评估结构并共同推进打样？

禁止出现材料方案、价格、MOQ、承重、交期、包装和地址。索要图稿或主动问参数、MOQ、样品费、报价算 `implicit_engagement`；“你好/在的/稍等”最多澄清一次；明确不配合则停止。

### core-feasibility

- `locked-drawing`：只问整体能否按图落地，以及必须调整的位置或生产风险；不逐项重问图纸事实。
- `collaborative-design`：可问核心方向能否实现、厂家建议做法和主要风险。

厂家说“按图没问题/没有调整”，只保存为书面能力声称，并标记 `sample_test_required=true`；不等于实物验证或合格。任意后续阶段若厂家明确更正核心整体做不了，立即停止；局部颜色或非核心材料不能做不淘汰整厂。

### 上下文理解

- 回复判断必须同时读取最新真人原话与`messageId`、上一条已验证出站文字及问题映射、当前阶段、图纸送达证据和历史已答字段，不允许只看孤立关键词。
- 单问后的“可以/是的/没问题”只能绑定该问；图纸后的泛化“可以”还需针对核心结构确认，不得直接标记合格。多问后的泛化肯定保持含糊。
- 只有上一条在问是否愿意看图时，“我可以看看吗”才是索图与合作信号；已送达图纸不重发。
- “在的/稍等/已转研发/我问生产/表情”只继续读取，不消耗第二条阶段问话。
- 厂家反问成本、尺寸、数量、颜色或再要图时，只用当前Brief已有口径回答并拉回本阶段；未提供的数字不得编造。
- 无服务器`messageId`、无法唯一映射、存在冲突或敏感动作时，自动写入为0，转人工复核。

### material-options

默认按“交付结果”沟通：用户没有指定材料，并且没有明确要求成本/耐用对比时，只问并记录最终样品实际采用的关键材料，用于追溯；不强制两套十项材料方案。
同一阶段还要取得厂家成熟尺码体系、各尺码适用体重、承重口径和测试方法；这些只保存为有原话/messageId的supplier proposal，样品前由用户选定，不回写为confirmed。

只有当 `OutputAcceptanceBrief.materialComparisonRequired=true` 时，才启用下列成本型/耐用型对比：

第一条只问关键部件分别采用什么材料。第二条根据回答动态补：

- 基线仍含糊：只补部件—材料对应和方案类型。
- 基线清楚：问成本型、耐用型分别改变哪些部件，变化项的材料、关键规格和差异理由；未变化项必须有厂家“其余相同”的原话。

两次仍含糊时，继续商务，但写入：

```text
technicalUnderstanding=insufficient
quoteComparability=not-comparable
qualificationBlocker=material_mapping_unclear
```

不得进入可打样合格名单。

### commercial-terms

第1条最多2问：MOQ/经济下单量/对应阶梯价；各档币种、计价单位、税运口径。

第2条最多2问：样品数量/范围/费用/周期；量产周期及 Brief 优先的包装或替换件价格。

不预设采购量。必须分别保存 `planned_quantity / sample_quantity / minimum_order_quantity / economic_order_quantity / quantity_tier_price`。

### final-review

只展示：已确认、厂家声称、未验证、冲突、缺项。若需要补问，只能生成一家厂家、一条 `manual_followup exactText`，重新预览并精确审批。

## 6. 材料方案V2（用户明确要求时）

材料不是10项问卷。证据结构为：

- 共同部件基线；
- 成本型变化；
- 耐用型变化；
- 厂家明确的“其余相同”；
- 共享或逐档商务条件。

技术可比较要求：所有关键部件材料对应明确；两档变化部件均有材料、关键规格、差异理由；每项绑定连续原话和 `messageId`；无未解决冲突。

商务完整要求：价格影响或数量档报价、MOQ、样品费和周期、量产周期；共享条件必须由厂家明确“两套相同”，不得静默继承。

只有 `technicalComparable && commercialComplete` 才可展示“可比较”。用户接受方案后只生成新 Brief 草稿并重新审批，不自动承诺打样、下单或采购。

## 7. 发送、附件与证据

- 只读找厂按公司、`memberId`、`loginId` 去重；保留Offer和工厂证据。
- 同一1688账号全局 `concurrency=1`。
- 发送后立即回读；exact出站文字和全新旺旺 `messageId` 同时存在才成功。
- 空输出/异常先回读，禁止盲重发；风险控制立即冻结队列。
- X项目顶部固定提供 `x-factory` 自助验证卡：登录失效、滑块、验证码或普通访问风控时，用户点击“打开1688验证窗口”，在专用窗口完成验证后点击“检测并恢复”。系统必须先通过一次固定只读探测才能解冻；`SEND_UNVERIFIED`、写任务租约过期或任何不明发送状态不得通过该按钮恢复。
- 附件必须逐份×逐厂家审批。自动范围仅JPEG/PNG且≤5MiB；PDF转逐页图片后必须重新预览批准。
- 附件成功证据：批准SHA → 本地复验 → upload objectId/URL → 发送帧引用同一对象 → 全新服务器messageId。DOM预览不算。
- `SEND_UNVERIFIED` 只能只读对账；若仍无objectId和服务器messageId，永久保留不明证据并隔离该厂家/附件包，绝不声明未发送后重试。隔离后仅可释放其他厂家的安全只读任务。
- `PACKAGE_SNAPSHOT_STALE`与`SEND_UNVERIFIED`必须分开：若文字已有exact服务器`messageId`，附件没有任何upload objectId/URL/messageId/fingerprint，且新增真人回复不含拒绝或敏感动作，可以按最新回复水位重建附件快照；只发送附件，绝不重发已验证文字。存在任何远端附件证据时仍按发送不明隔离。
- 已冻结在批次快照中的同一张草图，可在厂家明确愿意看图或主动索图后按逐厂grant自动发送；更换草图、Brief或批次外厂家必须重新审批。
- 站外联系、地址、付款、下单、模具和采购承诺始终单独人工审批。
- 附件自动发送必须由独立开关控制，普通1688执行开关不能隐式开启。

## 8. 判定与报告

“可以”“能定制”“按图能做”都不能单独标记 `qualified-for-sample`。技术理解不足、材料错配、报价基础不清、证据缺失或冲突未解，必须保持 blocked/pending。

报告包含候选、Offer、工厂证据、厂家原话与messageId、阶段、第1/2条、已回答/含糊/缺项、材料理解、报价可比性、sample-test-required和最终人工审核五栏。AI归纳与厂家原话分开。

接入X时，X数据库是唯一业务状态源；本地批次目录只保留CLI档案和原始执行证据。状态契约见 [state-schema.md](references/state-schema.md)，需求采集见 [intake-template.md](references/intake-template.md)。

## 发送前最后检查

- 找货策略版本为 `stock-first-custom-fallback-v1`，定制沟通版本为 `human-staged-v3`，供应商网络版本为 `core-pool-first-v1`。
- 同一产品只有一个项目，现货搜索与定制供应商准备同步启动。
- 只有进入定制兜底后才可生成 `human-staged-v3` 外发预览。
- 已先完成老厂池匹配；新厂若未解锁则外发任务必须为0。
- 老厂复用首询走 `seller chat --no-card`，仍须exact文字审批与全新messageId回读。
- contactIntent、设计模式、锁定事实和部件清单已由用户确认。
- 首询只问合作意愿。
- 厂家实际看到的每条消息不超过2个自然问题。
- 图纸事实不会被重复问。
- 附件权限逐份逐厂。
- 合格标准、监听和停止条件明确。
- 发送程序没有历史产品硬编码。
