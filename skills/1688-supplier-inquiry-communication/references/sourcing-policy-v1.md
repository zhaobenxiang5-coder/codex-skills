# 统一找货策略 V1

版本：`stock-first-custom-fallback-v1`。

## 单项目目标

一个产品只有一个业务项目。用户只点击一次“开始找现货和合适供应商”：

1. 根据用户批准的图片、链接、关键词和 `OutputAcceptanceBrief` 召回1688 Offer。
2. 现货候选和定制供应商候选同时准备，但使用独立状态、幂等键和证据表。
3. 前台先显示可原样测试的现货；无合适结果时无缝显示已准备的定制供应商。

## 现货准入

只有同时满足以下条件才能进入交接：

- 商品不需要改结构、版型、核心功能、连接方式或尺寸体系；
- 能以商品当前形态直接拿样做市场/使用测试；
- 已核验页面信息没有与用户硬性验收要求冲突。

外观相似但需要修改的Offer一律是 `reference-only`。页面标题或图片相似不足以自动标记 `handoff-ready`；缺少结构化核验时必须 `needs-verification`。

## 交接边界

交接只修改X的业务状态并生成卡片：

- 不联系卖家；
- 不发图；
- 不下单或付款；
- 不自动上架；
- 不把商品价格当作定制报价。

用户接收现货后只暂停未执行的定制扩展，已获得的供应商证据保留。用户放弃现货时，可直接继续现有定制结果。

## 定制兜底

定制供应商的核心评价是能否按方案交付并对样品、质量、报价和交付负责，不以“自有全部工序”为硬门槛。只有进入该兜底时才启用 `human-staged-v3`。

定制兜底固定采用`core-pool-first-v1`：先按品类赛道和工艺能力匹配1～3家当前仍合格的优选/核心老厂；同时只读准备新厂。老厂逐厂精确审批并用`seller chat --no-card`联系，不绑定无关Offer。老厂尚未全部拒绝、超时或被用户标记不匹配时，新厂外发保持锁定；用户手动提前解锁必须写原因。

新厂进入联系名单前只做保守初筛：`likely-manufacturer / likely-hybrid / likely-trader / unknown`并逐条显示依据。平台标签、企业名称或单一自述不能独立升级为真实工厂；透明外协只有在工序披露且该厂对开发、质检、报价和交付负责时才可通过。

未找到现货是正常结果，不重新建项目、不要求用户重新搜索、不触发卖家或厂家写操作。
